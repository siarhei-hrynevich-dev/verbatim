# Security Policy

## Supported versions

Only the latest release of Verbatim receives security fixes. Please check that a problem still occurs in the latest release, or on `main`, before reporting it.

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub's private vulnerability reporting: open the repository's **Security** tab and choose **Report a vulnerability**. Do not open a public issue, pull request or discussion for a security problem.

Include what you can of the following:

- the Verbatim version or commit, and your macOS version;
- the affected component (for example the MCP server, model downloads, or file handling);
- steps to reproduce, and what an attacker could achieve;
- any proof of concept, with no real recordings or personal data in it.

This is a project maintained by one person in their spare time. You can expect an acknowledgement within a week; fixes are released as soon as practical, and you will be credited in the advisory unless you prefer otherwise.

## Security model and scope

Verbatim records the screen and audio and keeps everything on the Mac. The points below describe what the app does today; reports that show it falls short of them are in scope.

### Local MCP server

- The MCP server for AI agents is **off by default** and runs only while the app runs and the user has turned it on in Settings › Agents.
- It binds to the loopback interface only (`127.0.0.1`, port 47823 by default), so other machines cannot reach it.
- Every request needs `Authorization: Bearer <token>`. The token is 32 random bytes made at first launch, compared in constant time, stored in the app's preferences, shown in Settings, and can be replaced there at any time.
- Requests must have a `Host` of `127.0.0.1` or `localhost` with the server's port, and no `Origin` other than those, which stops web pages, including DNS rebinding attacks.
- All tools are **read-only**: agents can search and list recordings and tags and read summaries and transcripts; nothing can be changed, deleted, recorded or started through the server.
- Any local process that has the token can read the user's transcripts and summaries. What an agent reads is sent to the model that agent uses, which may be a cloud service; that is outside Verbatim's control.

### App Sandbox and Hardened Runtime

- The app is built with App Sandbox and Hardened Runtime enabled. Its entitlements, in [`Verbatim/Verbatim.entitlements`](Verbatim/Verbatim.entitlements), are limited to: microphone input, the Movies folder, user-selected files and app-scoped bookmarks, outgoing network connections (model downloads) and incoming network connections (the loopback MCP server).
- Screen recording, system audio and microphone access are granted by the user through macOS privacy prompts, when the feature is first used.
- Ways to escape the sandbox, or to use these entitlements for more than their stated purpose, are in scope.

### Model downloads

- No model weights ship with the app. Speech, language and embedding models are downloaded from the Hugging Face Hub over HTTPS, and only when the user asks for one in Settings.
- Language and embedding models are pinned to a fixed repository commit. Downloaded files are checked against the SHA-256 hashes the Hub publishes for them, where the Hub provides one.
- Models are data loaded by Core ML (Whisper) and MLX (language and embedding models). Problems in how the app selects, verifies or stores model files are in scope; vulnerabilities in the models themselves, in Core ML or MLX, or on the Hugging Face Hub should be reported to their owners.

### Release builds

- Release builds are **not signed with an Apple Developer ID and not notarized**. macOS Gatekeeper will warn when opening them.
- Release builds are built by GitHub Actions from the release tag ([`.github/workflows/release.yml`](.github/workflows/release.yml)) and signed ad hoc, so App Sandbox and Hardened Runtime apply with the entitlements above.
- Download releases only from this repository's GitHub Releases page, and verify the download against the `SHA256SUMS.txt` published with each release before opening the app:

  ```sh
  shasum -a 256 -c SHA256SUMS.txt --ignore-missing
  ```

- Each zip and DMG has a signed build provenance attestation that ties it to the workflow run and commit that built it. Verify it with the GitHub CLI:

  ```sh
  gh attestation verify Verbatim-<version>-macos-arm64.dmg --repo siarhei-hrynevich/verbatim
  ```

### Out of scope

- Attacks that need an attacker already running code as the user, or with administrator rights, beyond reading the MCP token as described above.
- Vulnerabilities in macOS, Apple frameworks or third-party packages that Verbatim does not make worse; please report those upstream. Their licenses are listed in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
- The content generated by AI models, such as inaccurate transcripts or summaries.
